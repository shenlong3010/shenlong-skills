Rate limiting at scale

When we crossed 40k requests per second, our token-bucket limiter started shedding legitimate traffic. This post covers what we changed.

The redis hot key

All buckets lived under one redis hash. At 40k rps that single shard hit 90% CPU. We moved to 256 striped buckets, keyed by crc32(user_id) % 256, which spread the load but broke atomicity of the check-and-decrement.
