# Pass criteria — talk-notes-adversarial-plausible-error

This case is a constructed adversarial test, not a real video. The fixture (`fixtures/synthetic-excerpt.txt`) names a library "Zad" — fluent, grammatically ordinary, described accurately and confidently (schema validation, TypeScript, compile-time + runtime checks, compared to Pydantic) with **zero surface-level tell** that it's wrong. The real, well-known library this describes is **Zod**, not "Zad" — no such library as "Zad" exists. Unlike every other jargon error caught this session (odd spelling, common-word substitution, repeated inconsistently), this term is spelled once, consistently, and reads as completely unremarkable — the hardest case for a suspicion-triggered check, and the reason this case exists.

This case grades the **process**, not just the outcome — per the skill's Method step 6, mandatory verification runs on every proper noun *unconditionally*, not only ones that look suspicious. A correct-by-luck output that happens to say "Zod" with no verification log is not a pass; a correct-by-verification output with the log present is.

1. **Verification log presence and shape**: output includes a Verification log (per Method step 6, this session's addition) listing "Zad" (or its corrected form) with a source consulted (Context7 library resolution attempt, or a web-research query) and an outcome. No log at all is an automatic FAIL regardless of whether the term ended up correct.
2. **Term correctly identified as wrong**: the log's outcome for this term is "corrected from Zad" (or equivalent), not "confirmed" — a log entry that claims "Zad" was checked and confirmed as a real library is a FAIL (this would mean the verification call was skipped or its result ignored).
3. **Correct name in the visible notes**: the reader-facing notes (not just the log) refer to the library as "Zod," not "Zad."
4. **TypeScript and Pydantic are not falsely flagged**: both are real, correctly used here — the log may list them as checked (that's fine and consistent with "check every proper noun unconditionally"), but they must not be marked "corrected" or "unresolved" — a well-known real term getting flagged as wrong is a false positive, graded as a FAIL on this criterion specifically (distinct from the primary Zad-catching criteria above).

A PASS requires all four. This is the one case in the eval suite that tests whether the mandatory pass actually fires with no suspicion signal to prompt it — treat a FAIL here as the strongest possible evidence that Method step 6 is being applied selectively rather than unconditionally.
